# koko TUI 协议（2026-10-25 重新逆向）

> koko 是 JumpServer 的终端服务，只能在 **2222 端口**说它自己那套全屏 TUI。
> 没有 WebSocket 通道，没有 `host:asset` 语法，`ConnectionToken` 也不是 SSH 凭据。
> **唯一可编程的路径**就是：开 PTY → 在它的界面上打字 → 读屏幕。

⚠️ **koko 的界面文案变过一轮。下面这份是当前实测的，照旧记录写会全盘失败。**

## 1. 当前流程

```
等面板       → 提示栏出现 "enter:连接"（行计数器 "1-34/49" 也能用）
"/"          → 搜索框打开（标题变成 "我的资产 · 搜索:"）
输入关键字    → 框里显示 "我的资产 · 搜索:<关键字>"
Enter       → 执行搜索（提示栏出现 "x:清除搜索"）
             → 搜不到则显示 "▶ 没有匹配的资产"
Enter       → 选中匹配到的资产
Enter       → 接受账号，落到 shell 提示符
```

## 2. 新旧对照

| 环节 | 旧（**已失效**） | 现在（2026-10-25 实测） |
|---|---|---|
| 面板就绪信号 | 状态栏含 `Ctrl+C退出` | 提示栏含 `enter:连接`；`q:退出` 取代了 `Ctrl+C退出` |
| 打开搜索框 | `Ctrl+U` 顺带聚焦 | **必须按 `/`** |
| 执行搜索 | 输入即过滤 | 输入后**还要再按一次 Enter**（提示栏写 `enter:搜索`） |
| 搜索生效信号 | `清空搜索` | **`x:清除搜索`** 出现在提示栏 |
| 搜不到 | `没有匹配资产` | **`没有匹配的资产`**（多了个「的」） |
| 连接中横幅 | — | `ssh://<user>@<资产> 正在连接 <user>(<user>)@<地址>` |

## 3. 三个坑（都踩过）

### 坑 1：面板画出来了 ≠ 能收输入

面板约 1 秒就画好，但**此时输入还没被接收**，第一个 `/` 会被**整个吞掉**。
⇒ `/` 要**带延迟重发**（代码里 `openSearchBox` 最多试 4 次）。

### 坑 2：搜不到时列表不会变空

搜不到 → 显示「没有匹配的资产」，但**列表保持原样**。
再按 Enter 会选中**第一行** —— 直接连到**错误机器**。

⇒ 必须**先确认搜索生效**（`x:清除搜索`）再确认选择。

### 坑 3：连上之后要核对是谁

连接横幅会报出 `ssh://<user>@<资产>` 和 `@<地址>`。
把它跟请求的资产比对，不一致就是**选错行了**。

**连错对象比失败更糟** —— 失败会被人看见，连错机器会「成功」返回错的结果。

## 5. 怎么抓当前屏幕

用 `ssh` + `x/crypto/ssh` 开一个裸 PTY，把 stdout 原样 dump 出来即可：

```go
sess.RequestPty("xterm", 40, 220, modes)
sess.StdinPipe(); sess.StdoutPipe(); sess.Shell()
// 读 10 秒，把带 ANSI 的原始内容打出来，再剥 ANSI 看结构
```

仓库里 `internal/repository/koko/debug_probe.go.txt` 是当年的探针（不是构建的一部分），
可以照着改。
